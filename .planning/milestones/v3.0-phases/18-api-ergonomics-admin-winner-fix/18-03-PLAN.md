<objective>
API-04 (part 1 of 2): the data-access foundation for admin rotation CRUD. New `src/modules/
admin/` write module — contract types + a Pool-injected, transactional `PgAdminRotationRepository`
that creates/updates/deletes rotations with a server-derived slug and an empty-rotation delete
guard. Per D-04 this is a WRITE module (handlers/repos take `pool: Pool` + auth options
directly) — the public-stats read-model triplet does NOT apply.

Purpose: isolate the transactional DB surface (slug derivation, constraint→signal mapping,
dependency pre-check) so the route layer (18-04) is thin and the data access is independently
testable against real Postgres.
Output: `AdminRouteOptions`, `AdminRotationRepository` contract, `PgAdminRotationRepository` impl.

This is a NEW directory but NOT a new pattern — it mirrors `requests/routes/workflow-applier.ts`
(withClient begin/commit/rollback, $n-bound SQL) and `requests/routes/models.ts` (options/contract).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| route handler → repository | rotation name / dates arrive from an authenticated admin but are still untrusted input crossing into SQL |
| repository → DB | every value crosses into a parameterized query; constraints (unique, check, FK) are the integrity boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-07 | Tampering (SQL injection) | create/update/delete SQL | mitigate | All values `$n`-bound via withClient client.query arrays; no string interpolation; slug derived by slug_base($1) in SQL, never from client |
| T-18-08 | Tampering (data destruction) | deleteRotation | mitigate | Dependency pre-check (replays/commander_side_stats/bounty_points) in the SAME transaction refuses delete of non-empty rotations → has_dependents; only empty rotations deletable (D-04 LOCKED) |
| T-18-09 | Tampering (mass assignment) | create/update input | mitigate | Input restricted to name/startsAt/endsAt; slug is server-derived (not client-settable); id/created_at never accepted from the body |
| T-18-10 | Repudiation / integrity | constraint violations | mitigate | name UNIQUE (23505)→409 and ends_at>starts_at CHECK (23514)→422 surfaced as typed signals; DB constraints are the source of truth, not handler-side checks alone |
| T-18-SC | Tampering | npm/pip/cargo installs | mitigate | Zero new runtime dependencies this phase (D-domain: additive on shipped stack) — no install tasks; if any appear, halt and require the package-legitimacy gate |
</threat_model>
