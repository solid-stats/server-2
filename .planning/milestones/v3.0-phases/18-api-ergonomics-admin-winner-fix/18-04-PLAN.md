<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → admin route | unauthenticated/non-admin callers attempt rotation mutations; the role guard is the primary boundary |
| route → repository | request body crosses into the transactional repository (parameterized in 18-03) |
| API → web consumer | admin routes are in the public OpenAPI contract (web consumes it) but require an admin session |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-11 | Elevation of Privilege | POST/PUT/DELETE /admin/rotations | mitigate | `requireRole(options.auth, "admin")` preHandler on EVERY mutation route (admin only, not moderator); 401 unauth + 403 missing-role enforced before the handler runs; proven by the moderator→403 + unauthenticated→401 route tests |
| T-18-12 | Spoofing | session cookie | mitigate | Auth resolved via currentUser(options.auth, request.headers.cookie) (existing session store); routes never trust a client-supplied user/role field |
| T-18-13 | Tampering (mass assignment) | RotationBody | mitigate | Body restricted to name/startsAt/endsAt; slug not accepted (server-derived in 18-03); id only via :id param (uuid format) |
| T-18-14 | Repudiation | admin mutations | accept | v1 has no admin-rotation audit trail (D-04 scope: CRUD only; moderation actions cover the winner-fix path separately). Rationale: low-volume admin-only surface; audit is a follow-up if needed |
| T-18-15 | Information Disclosure | admin route error bodies | mitigate | Errors are `{ message }` only; no internal pg error text leaked; leak-guard sweep over /admin/rotations bodies added in 18-05 |
</threat_model>
