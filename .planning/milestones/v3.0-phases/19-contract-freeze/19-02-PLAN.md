Add the CI OpenAPI breaking-change classification gate (the core new work of Phase 19) as a separate `contract-diff` job in `.github/workflows/cd.yml`, confirm the existing `verify` job already satisfies the PostgreSQL integration freeze gate (FREEZE-04 — verify-and-keep, do NOT rebuild), document the semver bump policy in the README contract section, and surface the GitHub branch-protection requirement as a human-verify checkpoint.

Purpose: Make the frozen `1.0.0` contract hard to break accidentally. The gate classifies the diff between the PR's base-branch artifact and the PR-HEAD artifact: additive/backward-compatible changes pass freely (minor-level), while ERR-level breaking changes fail the job unless the PR intentionally bumps the major version and updates the committed baseline. The gate sits ON TOP OF the existing `openapi:verify` byte-equality drift gate (kept in Plan 01), not instead of it.

Output: One new CI job, one README section, one confirmation of the existing PG freeze gate, one branch-protection checkpoint.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner -> third-party action | The runner fetches and executes the oasdiff action; a compromised/mutated action could tamper with the gate result. |
| PR author -> protected branch | A PR proposes contract changes; the gate + branch protection decide whether they can merge. |
| committed artifact (base) -> committed artifact (revision) | oasdiff compares the base-branch spec against the PR-HEAD spec to classify breaking changes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-04 | Tampering / Elevation | oasdiff GitHub Action (third-party) | mitigate | Pin `oasdiff/oasdiff-action/breaking@v0.0.56` to the exact immutable tag (never a floating `@v0`); CI-only with no `package.json`/runtime reach (Security Domain V14). |
| T-19-05 | Tampering (silent contract drift) | contract-diff gate enforcement | mitigate | Branch-protection checkpoint (Task 3) marks `Contract diff` + `Verify` as required status checks so the gate blocks merges rather than being advisory (RESEARCH Open Question 2). |
| T-19-06 | Tampering (false-negative gate) | oasdiff base resolution | mitigate | `actions/checkout@v6` with `fetch-depth: 0` + `if: pull_request` so the base ref is present and the diff is real, not trivially empty (RESEARCH Pitfall 2). |
| T-19-07 | Information Disclosure | CI step output / secrets | accept | The contract-diff step takes no secrets and emits only diff classification of the public artifact; no credentials are exposed in the new step. |
| T-19-SC | Tampering | npm/pip/cargo installs | accept | No package-manager installs in this phase; oasdiff is a CI-only GitHub Action (Go binary), not a registry package — npm legitimacy gate is N/A (RESEARCH Package Legitimacy Audit). |
</threat_model>
