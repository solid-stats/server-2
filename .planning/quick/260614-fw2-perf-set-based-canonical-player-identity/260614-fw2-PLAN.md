<objective>
Rewrite `ensureNameFallbackIdentities()` in the per-rotation statistics recalculation repository to be set-based: one batch resolve against the pre-insert DB snapshot, an ordered in-memory replay that decides which fallback identities to create, and two multi-row inserts — replacing the current per-occurrence SELECT-plus-conditional-2-INSERT loop. This is the second perf bug after F7; F7 made the outer rotation loop set-based, this makes the inner identity resolution set-based.

Purpose: The inner loop runs a ~9ms `canonical_players LEFT JOIN player_nicknames` lookup once per unique `(name, timestamp)` occurrence (thousands per large rotation, e.g. R11 = 3710 replays), giving ~15-20 min/rotation and ~3h full-corpus ETA. Collapsing it to O(1) round-trips is the named bottleneck.

Output: A behavior-preserving (byte-identical aggregates AND fallback rows) set-based `ensureNameFallbackIdentities`, plus an extended integration parity test that stresses fallback identity creation. The helper stays drop-in for both the `*ForRotation` and `*ForParserResult` call paths.
</objective>

    - An occurrence that matches a pre-existing canonical player under the EXACT original predicate (`lower(display_name) = lower(name)` OR active-nickname-window match at the occurrence timestamp) creates nothing.
    - An occurrence with no pre-existing match whose `lower(name)` was already scheduled earlier this run creates nothing (the original loop would have matched the just-created fallback via display_name, which is timestamp-independent).
    - Otherwise exactly one fallback canonical_players row (display_name = name) and one player_nicknames row (nickname = name, observed_from = occurrence timestamp, observed_to null, evidence `{ source: "parser_artifact_name_fallback" }`) are created.
    - Same name at two timestamps with no pre-existing match ⇒ exactly one fallback canonical player (first occurrence creates it; second is guarded by createdLowerNames).
  </behavior>
  <action>
    Replace the body of `ensureNameFallbackIdentities(client, parserResults)` (currently the per-occurrence SELECT + conditional 2-INSERT loop, repository.ts L549-599). Keep the signature, name, file, and call site (`loadPlayerIdentities` awaits it) byte-identical — it must stay drop-in for both `*ForRotation` and `*ForParserResult`. Do NOT touch `loadPlayerIdentities` (already set-based), `uniqueNameOccurrences`, the `*ForParserResult` audit semantics, the legacy-public-export contract, or the `ops:stats:recalculate` report shape.

    Step 1 — reuse occurrences: call `uniqueNameOccurrences(parserResults)` to get the ordered, deduped, empty-name-skipped list. If empty, return early. Build two parallel arrays: occurrence names and occurrence timestamps (Date), index-aligned.

    Step 2 — one batch resolve against the PRE-INSERT snapshot: run a single `client.query` that takes the two arrays via `unnest($1::text[], $2::timestamptz[]) with ordinality as occ(name, ts, idx)` and returns the ordinality `idx` of every occurrence for which a matching canonical player EXISTS under the EXACT original predicate — `lower(cp.display_name) = lower(occ.name)` OR (`lower(pn.nickname) = lower(occ.name)` AND `(pn.observed_from is null or pn.observed_from <= occ.ts)` AND `(pn.observed_to is null or pn.observed_to >= occ.ts)`), via a correlated `exists (select 1 from canonical_players cp left join player_nicknames pn on pn.player_id = cp.id where ...)`. Mirror the `= any(...)` / set-based style of `loadPlayerIdentities` and `assignRotationsForCurrentReplays` in full-run.ts. Collect the returned indices into a Set of matched ordinality values. Note `with ordinality` is 1-based — map back to the 0-based occurrence array consistently.

    Step 3 — ordered in-memory replay: iterate occurrences in original order maintaining a `createdLowerNames` Set<string>. For each occurrence: if its index is in the matched set ⇒ skip; else if `name.toLowerCase()` is in createdLowerNames ⇒ skip; else ⇒ push the occurrence to a `toCreate` list and add `name.toLowerCase()` to createdLowerNames. Do NOT mutate the DB during this pass — the matched set was computed against the pre-insert snapshot and the createdLowerNames guard replicates the loop's later-occurrence behavior.

    Step 4 — two multi-row inserts (only if `toCreate` is non-empty): first `insert into canonical_players (display_name) select * from unnest($1::text[]) returning id` with display_names in `toCreate` order, capturing returned ids in row order (Postgres returns INSERT...SELECT rows in the select's input order; rely on the unnest order). Then `insert into player_nicknames (player_id, nickname, observed_from, evidence) select * from unnest($1::uuid[], $2::text[], $3::timestamptz[], $4::jsonb[])` pairing each returned canonical id with its `toCreate` name, the occurrence timestamp, and `JSON.stringify({ source: "parser_artifact_name_fallback" })` for every row (observed_to left default null, exactly as today). If the canonical insert returns fewer ids than requested, throw the existing-style error ("canonical player fallback insert did not return id"). Preserve the exact evidence JSON string and observed_from = occurrence timestamp.

    Follow solidstats-server-ts-conventions for the raw repository query style and solidstats-shared-ts-standards (no `any`, strict types, no needless casts beyond the documented `::type[]` SQL casts). The `created_at` collapse (all fallback rows share one `now()`) is intentional and safe per CONTEXT — do not add per-row created_at.
