# Quick Task 260614-f14 — Summary

## What changed

Fixed the ~5% deaths undercount introduced by the F13a per-game cap (PR #17).
Server-2 aggregation only — the Rust parser and its `d`/`td` artifact are
untouched.

- `src/modules/statistics/service/service.ts` —
  `calculatePlayerAndSquadAggregates` no longer builds or consults
  `counterDeathReferences`. The pre-F13a suppression of the victim kill-row death
  path (`applyVictimDeath` and the `applySquadEvent` victim branch) is removed.
  Both the counter path (`player_counter` → `deaths_total`/`by_teamkills`) and the
  victim kill-row path now tally into the per-replay scratch maps
  (`replayPlayerDeaths`, `replaySquadDeaths`); `foldCappedDeaths` still collapses
  each replay's contribution to <=1 `total` and <=1 `by_teamkills`, so removing the
  suppression cannot inflate counts — it only stops the leak.
- `src/modules/statistics/service/tests/aggregates.test.ts` — added a hoisted
  `counterAndKillReplay` fixture builder and three tests: the leak repro (zero
  counter + victim kill row → `total:1`), a teamkill variant asserting
  `by_teamkills <= total`, and the N-distinct-replays invariant (died in 3 replays
  → `total:3`).

## Root cause (confirmed)

`counterDeathReferences` held `observedPlayerRef` for **every** `player_counter`
with a DEFINED `counterDeaths(payload)` — including explicit-zero counters
(`deaths_total:0` still yields `{total:0,…}`, which is defined). The victim path
was suppressed whenever `counterDeathReferences.has(String(victim_entity_id))`,
while the counter path (`applyCounterEvent`) dropped the death when its
`observedPlayerRef` did not resolve in `playersByEntity` or contributed 0 for an
explicit-zero counter. So for an entity with a present-but-non-contributing
counter plus a real victim kill row, the death was lost from **both** paths. The
two paths also key differently (counter: `observedPlayerRef`; victim:
`String(victim_entity_id)`), so any resolution mismatch leaked a death. With
F13a's per-replay cap already in place, the suppression was redundant — its only
remaining effect was this leak.

## The fix

Stop suppressing the victim path; let whichever path resolves the entity record
the death into the per-replay scratch map. The F13a cap (`foldCappedDeaths`)
guarantees <=1 death and <=1 teamkill death per replay, so double-counting between
the two paths collapses to exactly 1 and `by_teamkills` never exceeds `total`. The
all-time `deaths.total` therefore equals the number of distinct replays the player
died in — the target invariant and the legacy "games-died-in" semantics.
