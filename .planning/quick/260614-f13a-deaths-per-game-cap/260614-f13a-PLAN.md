# Quick Task 260614-f13a: Cap deaths at one per game per player (one-life model)

## Problem (root cause)

The statistics aggregation (`calculatePlayerAndSquadAggregates`,
`src/modules/statistics/service/service.ts`) summed per-event death evidence with
no per-game cap. Two sources inflated a player's death count beyond reality:

- **Counter events** (`player_counter` → `deaths_total` / `deaths_by_teamkills`)
  add their full magnitude via `incrementDeathsByCounter`. ACE down-and-revive
  produces multiple "killed" artifacts, so `deaths_total` for a single game can be
  3+.
- **Kill-row fallback** (`applyVictimDeath`) adds 1 per `kill`/`teamkill`/
  `unknown_kill` event whose victim is a known player, so duplicate kill rows count
  as extra deaths.

Both fed straight into the cross-replay aggregate, so a player who died once in a
game could be credited with several deaths.

DECISION (product owner): all Solid Games are **one-life** — a player dies at most
once per game. Legacy semantics are "games-died-in" (a boolean per game). Target =
match legacy.

DATA (verified): capping moves `sg` total deaths 295000 → 293744 vs legacy 297878
(−1.4%, within coverage tolerance); among games-exact players, capped deaths match
legacy 99.3%.

## Approach

Keep the raw parser `d`/`td` evidence untouched (no parser changes) and cap the
**per-replay contribution** in the aggregation:

- Tally each replay's death evidence into per-replay scratch maps
  (`replayPlayerDeaths`, `replaySquadDeaths`) instead of writing straight into the
  cross-replay aggregate.
- After a replay's events are processed, fold a **capped** contribution into the
  aggregate via `foldCappedDeaths`:
  * `deaths.total += (perReplayDeaths.total > 0 ? 1 : 0)`
  * `deaths.by_teamkills += (perReplayDeaths.by_teamkills > 0 ? 1 : 0)`
- Cap **both** consistently so `by_teamkills` can never exceed `total`.

Summed across the replays an entity appears in, `total` equals the count of games
it died in — exactly the legacy "games-died-in" semantics. The existing
`counterDeathReferences` suppression of the kill-row fallback (so a player with a
counter event is not double-counted by victim kill rows) is preserved; the cap
applies to whichever path contributed.

This stays entirely in the **service** layer (the aggregation owner) — no parser,
schema, repository SQL, or API contract changes
(`solidstats-server-ts-conventions` §A: keep each layer doing its own job).

## Tasks

1. **Service** (`service/service.ts`): add per-replay death scratch maps to the
   event context; redirect death writes (`applyVictimDeath`, `applyCounterEvent`,
   `applySquadEvent` victim branch, `applySquadCounterEvent`) into them; fold capped
   contributions into the player/squad aggregates after each replay.
2. **Unit tests** (`service/tests/aggregates.test.ts`): update the two existing
   expectations that change under the cap (counter `deaths_total:3` → 1; counter
   `deaths_by_teamkills:2` → `{total:1, by_teamkills:1}`); add cap-specific cases —
   3 death events in one replay → `total 1`; a teamkill death → `by_teamkills 1`;
   died in 2 replays → `total 2`; never died → `total 0`; a normal + teamkill death
   in one replay → `{total:1, by_teamkills:1}`.
