# Quick Task 260615-f13b — Deaths under-count: counter death signal read from stale `parser_events`

## Symptom (proven, staging post-fix #18)

- sg all-time `deaths.total` = **282720**; parser's own d>0 signal = **293744**
  (distinct (lower-name, replay) with artifact `d>0`). Recalc loses ~**11024**
  death-games vs the parser's own signal — a server-2 aggregation bug.
- Exemplar player **Zero** (`canonical_players.id =
  000a2ac8-443d-434c-9d30-ea8613c4c0ed`): recalc sg all-time games=894,
  deaths=621; parser has Zero with d>0 in **653** distinct sg replays ⇒ **32**
  death-games dropped while their GAME is counted.

## Root cause — CONFIRMED by instrumentation on real data (not code reading)

The recalc has two death sources in `service.ts`:
1. **counter path** — `player_counter` event with `deaths_total`/`deaths_by_teamkills`
   (`applyCounterEvent`), and
2. **victim kill-row path** — another player's kill-row names the victim's eid
   (`applyVictimDeath`).

Both read from the `events` array, which the repository builds from the
**`parser_events` table** (`loadParserEvents`). But:

- `parser_events` is re-persisted ONLY by the single-replay audit path
  (`recalculateParserResult` → `persistParserArtifact` → `replaceParserEvents`).
  The **bulk full-run** (`full-run-recalculation.ts`) NEVER re-persists events —
  it reads whatever `parser_events` already exist.
- For ~90% of current sg replays (1850 / 2059 with artifact `d` players), the
  persisted `parser_events` contain **0 `player_counter` rows**, while
  `raw_snapshot` carries the compact counters. (Staging count, query in
  `findings.sql`.) The counter death path therefore finds nothing.
- The player evidence (`resolvedPlayers`) AND games are built from
  `raw_snapshot`, so the game is counted; only the death — when it has no
  independent victim kill-row (null-killer / suicide / environmental / bleed-out
  `d>0` with no attacker) — is lost.

**Instrumentation evidence** (`instrument.ts`, real exported rows, real
`buildPlayerIdentityIndex` / `bestPlayerIdentityIndexed` / `playerIdentityMatchPriority`
/ `calculatePlayerAndSquadAggregates`): across 16 of Zero's d>0 replays, Zero
**resolves in all 16** (so the F12-timestamp/nickname-active hypothesis is
REFUTED — he matches via the time-ungated `display_name` priority-1 branch even
for pre-2026-05-10 replays), yet only 6 deaths are credited (3 via counter, 3 via
victim) and **10 are DROPPED** because for those replays `parser_events` has no
counter event for Zero's eid AND no kill-row names his eid as victim.

Concrete dropped replay: **9eb1a2ad-60b8-4692-8520-47d8362c207c (2021-05-14)**,
current prid `3662f461-e6e1-460f-a985-9902e17c6f9e`. raw_snapshot Zero =
`{d:1, nkd:1, eid:203}`; `parser_events` for this prid = 140 kill / 18
destroyed_vehicle / 6 teamkill / 1 diagnostic, **0 player_counter**; no kill-row
with `victim_entity_id=203` ⇒ death dropped, game kept.

So the bug is: **the death counter signal is read from the stale `parser_events`
table instead of the authoritative `raw_snapshot`.**

## Fix (minimal, service-layer + repository wiring)

Read the per-player counter death signal from `raw_snapshot` (the same source
already used for player resolution and games) and fold it through the existing
capped fold, instead of depending on `parser_events.player_counter`.

- Carry the artifact's compact counters (`d` → total, `td` → by_teamkills) onto
  the resolved player evidence in `resolvedPlayers` (repository), keyed by the
  resolved `playerId`/`squadId`.
- In `calculatePlayerAndSquadAggregates` (service), tally those counter deaths
  into the per-replay scratch maps alongside the existing victim path, then
  `foldCappedDeaths` as today. The `player_counter` EVENT path stays as a
  no-op-when-absent fallback (kept for the audit path / OCAP events), but the
  authoritative signal now comes from the artifact.

### Invariants preserved
- One-life cap: ≤1 `total` and ≤1 `by_teamkills` per replay (`foldCappedDeaths`).
- `by_teamkills ≤ total` (counter total = `max(d, td)`, same as `counterDeaths`).
- Games unaffected (player/replay set already from `raw_snapshot`).
- Parser / OCAP contract untouched; no schema or API change.
