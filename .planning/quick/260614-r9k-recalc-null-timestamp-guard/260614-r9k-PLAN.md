# Quick Task 260614-r9k: Guard the all-time recalc against NULL replay_timestamp

## Problem (root cause)

The full-run / all-time statistics recalculation crashed with
`TypeError: Cannot read properties of null (reading 'toISOString')` in
`uniqueNameOccurrences` (`src/modules/statistics/repository/repository.ts:838`).

`scopedCurrentResultsSql` builds the per-scope query over current replays. For the
**all-time** scope it loaded *every* current replay of the scope's game type —
including replays with a `NULL` `replay_timestamp` (the parity corpus has 1101 such
rows). When such a replay carries a **no-SteamID** player, identity resolution falls
through to the name-fallback path (`ensureNameFallbackIdentities` →
`uniqueNameOccurrences`), which keys each occurrence on
`row.replay_timestamp.toISOString()`. With a `NULL` timestamp that dereference throws.

The single-replay audit path already reports these as `missing_replay_timestamp` and
never recalculates them; only the all-time scope's broad scan pulled them in.

## Approach

Exclude `NULL`-timestamp replays from `scopedCurrentResultsSql` with
`and r.replay_timestamp is not null`. Rationale:

- They cannot be placed in time, so they have no rotation/all-time position.
- The all-time bucket's name-occurrence identity resolution keys on the timestamp.
- Recalculation already classifies them `missing_replay_timestamp` (never aggregated),
  so excluding them from the scope is behavior-consistent, not a new policy.

This is the narrowest, convention-conformant fix: the repository layer owns the SQL
and the row contract, so the guard belongs in the query, not in a downstream
service/usecase. (`solidstats-server-ts-conventions` §A: repository = data-access
adapter; keep each layer doing its own job.)

## Tasks

2. **Integration test** (`repository/tests/postgres.test.ts`): reproduce the crash
