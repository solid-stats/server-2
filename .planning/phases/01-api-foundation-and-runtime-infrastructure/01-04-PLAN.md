# Plan 01-04: Health, Metrics, and OpenAPI

<objective>
Replace the temporary liveness route with operations routes, register OpenAPI from route schemas, export the schema artifact, and validate it with `openapi-typescript`.
</objective>

<must_haves>
- D-06 through D-09: Fastify route schemas are the OpenAPI source of truth, not hand-maintained DTOs.
- D-17: `/live` only proves the process is running; `/ready` checks configured dependencies.
- D-18: `/metrics` exists with a Prometheus-compatible baseline.
- D-20: OpenAPI export and `openapi-typescript` validation are part of verification.
</must_haves>

<threat_model>
- T-01-08 OpenAPI exposure: internal routes can leak if blindly published. Mitigation: Phase 1 only registers operations routes and explicit schemas.
- T-01-09 Readiness secret leakage: dependency failures can expose credential-bearing URLs. Mitigation: readiness responses include `status`, `checks`, and sanitized messages only.
- T-01-10 Metrics abuse: metrics should be text/plain and not include secrets or request bodies. Mitigation: use `prom-client` default process metrics only in Phase 1.
</threat_model>
