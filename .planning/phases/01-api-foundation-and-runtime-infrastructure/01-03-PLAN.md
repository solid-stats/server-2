# Plan 01-03: Dependency Adapters and Local Compose

<objective>
Provide local PostgreSQL, RabbitMQ, and MinIO dependencies plus health-checkable adapters that the API process can use.
</objective>

<must_haves>
- D-10: adapters expose narrow `check()` and `close()` methods.
- D-11: PostgreSQL uses `pg`, with Kysely available for future explicit SQL-shaped access.
- D-12: S3 uses AWS SDK v3 with endpoint and path-style config.
- D-13: RabbitMQ adapter establishes connection/readiness only; parser message publishing is deferred.
- D-14 through D-16: local Compose is the only required dependency stack.
</must_haves>

<threat_model>
- T-01-05 Credential disclosure: readiness failures must not return `DATABASE_URL`, `RABBITMQ_URL`, or S3 secret values. Mitigation: adapter checks return service names and sanitized error codes/messages only.
- T-01-06 Hanging dependency checks: network checks can stall readiness. Mitigation: checks use bounded calls and `close()` methods.
- T-01-07 Object leakage: S3 readiness must not list or return object contents. Mitigation: check bucket existence/access only.
</threat_model>
