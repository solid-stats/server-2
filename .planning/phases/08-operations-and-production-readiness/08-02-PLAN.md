# Plan 08-02: Health Checks, Metrics, and Structured Job Logging

## Goal

Expose operational readiness for API dependencies and parser integration, publish Prometheus metrics for parser/job processing, and log parser job publishing failures with durable identifiers.

## Scope

- Add parser integration to the default readiness check set.
- Register parser/job operational metrics in the Prometheus registry.
- Connect parse job publisher publishing outcomes to metrics-friendly observer hooks.
- Emit structured parser job publish logs with `job_id`, `replay_id`, object key, parser contract version, and structured error payloads.
- Update docs and planning status.

## Implementation

1. Extend `src/infra/metrics/registry.ts` with parser job duration, parser job outcome, parser worker failure, and queue depth metrics.
2. Add parser integration readiness to `buildApp` defaults and production `server.ts` checks.
3. Add `ParseJobPublisher` observer/logger runtime options while keeping default no-op behavior for tests and callers.
4. Cover readiness, metrics exposition, queue depth observation, publish success logging, and publish failure logging in adjacent tests.
5. Document runtime surfaces and production metric/log expectations.
