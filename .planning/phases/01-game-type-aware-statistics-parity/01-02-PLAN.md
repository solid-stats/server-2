<objective>
Port the legacy `sg-replay-parser` classification spec (RESEARCH B) into server-2 as (1) a versioned typed
config module — `includeReplays` (3) + `excludeReplays` (16, deduped) + the fixed `['sg','mace','sm']` order
(D4) — and (2) a pure `classifyGameType()` that, given a mission name, the replay's distinct-player count,
the replay date, and the config, returns `'sg' | 'mace' | 'sm' | null` exactly per legacy rules. Then wire a
set-based repository step `classifyGameTypesForCurrentReplays()` on the full-run repo that writes
`replays.game_type` for every current-parser-result replay in one pass, mirroring F7's
`assignRotationsForCurrentReplays`. Also discharge the CONTEXT must-verify gate that server-2's seeded 20
rotations match the legacy ISO-week-snapped dates.

Purpose: `replays.game_type` is the grouping key every aggregation/export step in this phase reads; the
config + classifier own the *spec*, the repo step owns the *set-based write*. Splitting pure spec from the DB
write keeps the legacy rules unit-testable without Postgres (D2/D4).
Output: A `game-type/` submodule (config + classifier + unit tests), a set-based classify step on the
full-run repo, and a real-pg rotation-parity guard test.
</objective>
