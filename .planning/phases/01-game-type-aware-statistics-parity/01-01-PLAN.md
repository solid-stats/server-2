  <name>Task 1: Add the 0008 game_type + all-time migration</name>
  <files>src/infra/db/migrations/0008_game_type_aggregates.sql</files>
  <action>
    Create a NEW migration file `0008_game_type_aggregates.sql` (per D1/D2/D3). Do NOT edit any existing
    0001–0007 file — migrate.ts checksum-pins applied migrations and throws "checksum changed after apply"
    on any in-place edit, so all schema change for this phase is additive in 0008.

    The running engine is PostgreSQL 17 (docker-compose, prod, and k8s all pin `postgres:17-alpine`), so
    `UNIQUE NULLS NOT DISTINCT` (PG15+) is available — use it (Claude's-discretion item from CONTEXT D1
    resolved to NULLS NOT DISTINCT; do NOT use partial indexes).

    The migration MUST, in this order:
    1. `alter table replays add column game_type text;` (nullable; NULL = excluded per D2; no check
       constraint — classification writes only 'sg'|'mace'|'sm' or NULL, and a value set keeps it flexible).
    2. For each of `player_stats`, `squad_stats`, `bounty_points`, `commander_side_stats`:
       - `add column game_type text;` (nullable so a backfill/recompute can run; the all-time/per-type rows
         that recalc writes will set it).
       - `alter column rotation_id drop not null;` (D1 — `rotation_id IS NULL` = all-time bucket).
    3. Drop the existing rotation-only unique constraints and replace them with game_type-aware ones using
       NULLS NOT DISTINCT so a single all-time (rotation_id NULL) row per (player/squad, game_type) is
       enforced AND duplicates are rejected:
       - `player_stats`: drop `unique (rotation_id, player_id)`, add
         `unique nulls not distinct (rotation_id, player_id, game_type)`.
       - `squad_stats`: drop `unique (rotation_id, squad_id)`, add
         `unique nulls not distinct (rotation_id, squad_id, game_type)`.
       - `bounty_points`: drop `unique (rotation_id, player_id)`, add
         `unique nulls not distinct (rotation_id, player_id, game_type)`.
       - `commander_side_stats`: it has NO explicit unique today (RESEARCH A) — add
         `unique nulls not distinct (rotation_id, player_id, side, game_type)` (the commander triple +
         game_type per D1). Note `player_id` is nullable here already; NULLS NOT DISTINCT also collapses
         null player_id rows, which matches the existing one-row-per-(rotation,player,side) intent.
       Find the exact existing constraint names by inspecting 0001 (they are the table-level `unique (...)`
       definitions; Postgres auto-names them `<table>_<cols>_key`). Use
       `alter table ... drop constraint if exists <name>` with the auto-generated name, then add the new
       named constraints (give them explicit stable names, e.g. `player_stats_rotation_player_type_key`).
    4. `alter table player_stats add column is_show boolean not null default true;` (D3 — existing rows stay
       shown; recalc overwrites per scope).

    Keep the all-time row reachable by the assign/enumeration code: do NOT add any NOT NULL or FK change to
    `rotation_id` beyond dropping NOT NULL (the FK to rotations stays; NULL is allowed by an FK).
  </action>
