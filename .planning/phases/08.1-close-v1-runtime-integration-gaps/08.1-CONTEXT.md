# Phase 08.1: Close v1 runtime integration gaps - Context

**Gathered:** 2026-05-10
**Status:** Ready for planning
**Source:** v1.0 milestone audit

## Phase Boundary

Close the blockers found by `.planning/v1.0-MILESTONE-AUDIT.md` so the v1 backend has production runtime wiring, not only isolated route/service seams.

This inserted phase is urgent closure work after Phase 8. It does not add new product scope; it makes existing v1 requirements work end-to-end.

## Locked Decisions

- Runtime ingest must promote pending staging records through `IngestPromotionService`, using PostgreSQL as durable state.
- Runtime parse publishing must drain queued/retryable `parse_jobs` through RabbitMQ using the existing `ParseJobPublisher`.
- Runtime parser completion/failure consumers must call `PgIngestRepository.recordParserCompleted()` and `recordParserFailed()`.
- Parser completion and approved corrections must trigger the Phase 4 recalculation path, not a no-op.
- Public stats production startup must read from PostgreSQL aggregate tables instead of the empty read model.
- Auth, sessions, roles, requests, attachments, audit patches, and workflow records must move from in-memory production wiring to PostgreSQL-backed wiring or be explicitly blocked from milestone completion.
- Operations visibility routes under `/operations/ingest-staging` and `/operations/parse-jobs` require moderator/admin authorization.
- Phase verification and Nyquist artifacts must be restored for phases 05-08 before milestone archive.
