# Plan 08.1-01: Runtime Ingest/Parser Wiring and Operations Authorization

## Goal

Make production startup actually run the ingest and parse-job lifecycle, and protect operations read routes with roles.

## Tasks

1. Add admin/moderator authorization to operations ingest and parse-job read routes.
2. Add tests proving anonymous and non-privileged users cannot read ingest/parse job operational visibility.
3. Add runtime loop helpers for bounded polling without overlapping ticks.
4. Wire `IngestPromotionService.promotePending()` into production startup with configured batch/interval values.
5. Wire `ParseJobPublisher.publishQueued()` into production startup with a RabbitMQ confirming publisher.
6. Add parser completion/failure RabbitMQ consumers that call `PgIngestRepository.recordParserCompleted()` and `recordParserFailed()`.
7. Ensure shutdown closes worker loops and queue runtime resources.
8. Run targeted tests, typecheck, OpenAPI verification, and full `pnpm run verify` if feasible.

## Acceptance Criteria

- Operations read endpoints return 401/403 without moderator/admin role.
- Production `src/server.ts` starts ingest promotion and parse-job publishing loops.
- Production runtime consumes parser completion and failure messages.
- Retry/reparse-created queued jobs have a runtime publisher path to RabbitMQ.
- Verification artifacts document remaining gaps separately from this runtime slice.
