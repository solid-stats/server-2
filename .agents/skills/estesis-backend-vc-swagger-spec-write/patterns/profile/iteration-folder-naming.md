# Имя iteration folder — глобальный 3-значный индекс без пропусков

## Правило

Папка итерации должна называться `XXX_<slug>`, где `XXX` — трехзначный десятичный глобальный исторический индекс, идущий строго подряд для всего `changes/` и увеличивающийся только на 1 без пропусков. Индекс отражает порядок появления/согласования постановок, а не dependency order. Каждая папка соответствует одной immutable бизнес-итерации; отдельная папка для одной постановки допустима, если это отдельная бизнес-итерация.

## Когда применяется

- появилась новая папка в `changes/`;
- кто-то предложил пропустить номер или зарезервировать диапазон;
- кто-то предложил использовать суффикс вида `001_v2` или service-имя как корень папки;
- удалили промежуточную папку и появилась дыра в нумерации.

## Как проверить

- Получи отсортированный список `ls changes/`. Проверь, что префиксы идут `001`, `002`, ..., `NNN` без пропусков.
- Сверь номер новой папки со следующим свободным индексом по `CATALOG.md` и по фактическим папкам.
- Убедись, что `<slug>` после `XXX_` не повторяет имя сервиса как папка-агрегатор (например, `008_songs` для всех песенных постановок недопустимо); slug должен описывать бизнес-итерацию.
- Если в репозитории удалена папка (`git status` показывает `D changes/0NN_*`), уточни, не оставлена ли дыра в нумерации. Дыра допустима только если удаление сопровождается явным supersedes в более новой итерации.

## Severity и риск

MEDIUM. Нарушение разрушает глобальный исторический порядок и навигацию по `CATALOG.md`, ломает зависимости в `INDEX.md` (`Depends On` ссылается на конкретные индексы) и делает невозможной согласованную картину истории контракта. Пропуск номера или дублирование индекса требуют ручного исправления всех ссылок.

## Хороший пример

- `changes/020_resource_owned_content_studio/` — следующий по порядку после `019_resource_purchased_content/`, slug отражает бизнес-итерацию.
- `changes/021_resource_voice_range/` — отдельная папка для одной постановки, потому что это отдельная бизнес-итерация.
- `CATALOG.md:5-27` — итерации перечислены подряд от `001` до `023` без пропусков.

## Антипример

```
changes/
  019_resource_purchased_content/
  021_resource_voice_range/        # пропущен 020
  020_v2_studio/                   # суффикс _v2 и попытка переиздать
```

Правка: восстановить 020 или закрыть 020 явным supersedes; убрать `_v2`-суффиксы; обеспечить, что каждая последующая папка имеет следующий свободный индекс.

## Связанные паттерны

- [[iteration-no-rewriting-old-folders]] — старые папки не переписываются, новая папка получает следующий индекс.

## Заметки для ревьюера

- Папка `024_calendar_generic_cleanup` была удалена и поглощена `020_resource_owned_content_studio` (см. `changes/020_resource_owned_content_studio/CHANGES.md:131-144`). Это исключение зафиксировано в `CHANGES.md` через supersedes и не считается нарушением.
- Если разработчик предложил пропустить номер, чтобы зарезервировать его под параллельную работу, отказывайся — резервирование индексов прямо запрещено правилом контигуальности.
