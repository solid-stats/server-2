# Нумерация этапов внутри iteration folder

## Правило

YAML-файлы этапов внутри iteration folder именуются `XX_<scope>_<slug>.yaml` для последовательных этапов и `XX_YY_<scope>_<slug>.yaml` для параллельных подэтапов внутри одного `XX`. `XX` — двузначный десятичный номер этапа, идущий подряд от `01`. В одной папке может быть только один файл формата `XX_<scope>_<slug>.yaml` для каждого `XX`; если нужно несколько файлов внутри одного этапа, используется только форма `XX_YY_*`. `<scope>` обычно равно имени сервиса (`songs`, `resources`, `musicLabels`, `mainBackend` и т.п.); для общих схем, не принадлежащих одному сервису, используется `<scope> = shared`.

## Когда применяется

- добавляется новый YAML-файл этапа;
- перенумеровываются существующие этапы (например, после удаления промежуточного этапа);
- предлагается смешивать формы `XX_*` и `XX_YY_*` для одного `XX`;
- в имени появляется service-id, не совпадающий с реальным сервисом.

## Как проверить

- Проверь, что у каждого этапа в `INDEX.md` Stage Map есть соответствующий YAML-файл и наоборот.
- Сверь, что для одного `XX` либо есть единственный файл `XX_<scope>_<slug>.yaml`, либо есть несколько файлов `XX_YY_*`, но не одновременно оба формата.
- Сверь, что `XX` начинается с `01` и идет подряд (`01`, `02`, `03`, ...). Допустимы дыры только если этап целиком вытеснен (но `CHANGES.md` тогда обязательно фиксирует это).
- Сверь, что `<scope>` совпадает с одним из реальных сервисов из `registry/services/` или равен `shared` для шаренных файлов.

## Severity и риск

MEDIUM. Нарушение делает порядок реализации неоднозначным: разработчик не понимает, что нужно сделать раньше, а что — позже. Смешивание форм `XX_*` и `XX_YY_*` для одного `XX` создает конфликт между "это один этап" и "это набор параллельных подэтапов". Неверный `<scope>` ломает фильтрацию по сервисам в `CATALOG.md`.

## Хороший пример

- `changes/006_video_lessons/` содержит `01_resources_create_delete.yaml`, `02_01_resources_shop_library.yaml`, `02_02_resources_reviews.yaml`, `03_resources_admin.yaml` — корректно перемежает один-файловый `XX` и параллельные `XX_YY`.
- `changes/001_shared_status_errors/01_shared_status_single_error.yaml` — корректное использование `<scope> = shared`.
- `changes/020_resource_owned_content_studio/INDEX.md:46-50` — Stage Map описывает `01_01`, `01_02` параллельно и `02` последовательно поверх них.

## Антипример

```
changes/030_new_iteration/
  01_resources_create.yaml        # одиночный этап 01
  01_01_resources_update.yaml     # одновременно XX_YY для 01 — конфликт форм
  02_resources_delete.yaml
```

Правка: если нужно несколько файлов для `01`, переименовать одиночный `01_*` в `01_YY_*` и держать только параллельные подэтапы, либо объединить `01_01_*` в `01_*` и оставить только один файл этапа.

## Связанные паттерны

- [[iteration-parallel-stages-xx-yy]] — семантика параллельных подэтапов `XX_YY_*`.
- [[iteration-folder-naming]] — глобальный индекс папки не зависит от внутренней нумерации этапов.

## Заметки для ревьюера

- Имя `<slug>` в YAML обычно короткое и описывает scope действия (`create_delete`, `shop_library`, `reviews`, `admin`). Длинный `<slug>` допустим, но избегай дублирования слов с `<scope>`.
- Каждый следующий этап предполагает, что все предыдущие этапы этой же итерации уже реализованы. Если этап написан так, что не зависит ни от одного из предыдущих, проверь, нужен ли ему отдельный `XX` или это параллельный `XX_YY`.
